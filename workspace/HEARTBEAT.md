# HEARTBEAT.md

## Website-only mode
只做网站优化与更新相关工作。
忽略其他非网站任务。

## 网站自主决策
网站相关事项由我自主决定并执行，不需要再次向小苏确认；
除非涉及不可逆高风险操作（如删除大量数据）。

## 巡检执行要求（重心：功能与UI更新，不是纯检查）
每轮必须包含：
1. 前台/后台与关键链路快速可用性检查（简洁即可）
2. **至少 4-6 项“功能或 UI 的实际改动并落地”**（优先级高于检查）
3. 错误自动修复与记录（写入 memory/当天日期.md）
4. 输出本轮结果与剩余问题

执行约束：
- 不要只做健康检查；若仅检查无改动，视为未完成本轮目标。
- 优先做用户可感知的改进：交互、信息架构、加载体验、后台操作效率、稳定性细节。
- 每轮至少包含：1项前台交互/UI改动 + 1项后台功能改动 + 1项稳定性/性能改动，避免只做零碎微调。
- 若确无可改项，需先给出“为什么当前轮没有可执行改动”的具体理由，再回复 `HEARTBEAT_OK`。
